# submission_v2 — сабмит с минимальной нагрузкой на API

Самодостаточная папка: ровно эти файлы лежат в ZIP для платформы. Собрана от `submission_8` (балл 32),
модули `lc_*.py` — его плоские копии с правками ниже. Код в `legal_core/` (веб-прототип) не затронут.

## Проверить локально

```powershell
docker compose --profile eval up -d
Compress-Archive submission_v2\*.py, submission_v2\requirements.txt dist\submission_v2.zip -Force
python eval/local_platform.py --set demo --zip dist\submission_v2.zip
```

Сравнить с базой на тех же вопросах:

```powershell
python eval/local_platform.py --set demo --zip <путь к submission_8.zip> --reuse-baseline
```

Смотреть в `eval_runs/<время>/report.csv`: сколько ответов (`ours`) совпадает с эталоном (`golden`) по сути.

## Что изменено относительно submission_8

| Файл | Изменение |
|---|---|
| `solution.py` | Переписан. На вопрос — 1 эмбеддинг (только самая полная формулировка) и 1 вызов модели простым текстом. Потоков — `MAX_WORKERS` платформы (по умолчанию 2). Реранкер выключен. 429/5xx — пауза с учётом Retry-After и до 3 попыток; неотвеченные вопросы переспрашиваются вторым проходом в конце; заглушек нет (крайний случай — текст лучшего пункта). Зонд удалён. |
| `lc_prompts.py` | `TEXT_SYSTEM` = промпт submission_8 без JSON-части + «ответ обычным текстом, 2–6 предложений»; `text_messages()`. Пометки редакций в заголовках фрагментов, строка о дате события, правило 11 про оговорки. |
| `lc_pipeline.py` | `extractive_answer()` (ответ текстом пунктов), подсказки о редакции и оговорках для конвейера прототипа. |
| `lc_retrieval.py` | Другие редакции документа в контексте, если в вопросе есть дата события; поиск без эмбеддинга вопроса (`embed_fn=None`). |
| `lc_verify.py` | Поиск потерянных оговорок («если иное не установлено…») и их дописывание. |
| `lc_dates.py` | Новый: дата события из вопроса и применимость редакции. |

Не менялись: нарезка документов, настройки (`MAX_TOKENS` ≥ 3000), BM25, индекс, чтение базы.
